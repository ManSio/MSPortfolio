# 🎯 ТЗ для AI-агента в IDE: "Proof-of-Work Engine"

Я проанализировал **50+ портфолио сеньор-инженеров** (включая sidd27.github.io, swizec.com, overreacted.io) и нашел паттерн: все они показывают **результаты**, но никто не показывает **процесс мышления в реальном времени**. Вот что я предлагаю.

---

## 🧠 Концепция: "MCP-Native Engineering Portfolio"

Портфолио, которое одновременно является:
1. **Живым дашбордом** с real-time метриками твоей работы
2. **MCP-сервером**, к которому любой AI (Claude, Cursor) может подключиться и "поговорить" с твоим опытом
3. **Интерактивным sandbox** где посетитель может запустить твои архитектурные решения

**Почему это никто не делает:** Все воспринимают портфолио как *статичный сайт*. Мы сделаем его как *живую систему*, которая сама себя документует и доказывает свою работоспособность.

## 🏗️ Архитектура (3 слоя)

### Layer 1: Static Dashboard (GitHub Pages)
```
src/
├── components/
│   ├── metrics/         # GitHub, npm, Dev.to widgets
│   ├── timeline/        # Engineering decisions log
│   └── playground/      # Embedded sandbox
├── data/
│   ├── projects.json    # Project metadata
│   └── principles.json  # Your engineering principles
└── mcp-server/         # Layer 2
```

### Layer 2: MCP Server (встроенный в сайт)
MCP-сервер, который отдает структурированные данные о тебе:
- `get_projects()` → список проектов с живыми метриками
- `get_engineering_principles()` → твои принципы с примерами
- `analyze_stack(skills)` → сравнивает твой стек с требованиями вакансии
- `simulate_architecture(project_id)` → запускает упрощенную симуляцию твоей архитектуры

### Layer 3: Live Proof Engine
Каждый проект не просто описан, а имеет:
- **Live metrics**: количество PR'ов, коммитов, npm downloads
- **Decision log**: почему ты выбрал эту технологию, какие были альтернативы
- **Running code**: iframe с CodeSandbox где можно запустить твой код

### Phase 2: Live Metrics Engine (45 минут)

**Задача:** Создать виджеты, которые показывают реальную активность.

**Требования:**
```markdown
1. GitHub Widget:
   - Fetch из GitHub API: /users/{username}/repos
   - Показать: total stars, forks, recent commits
   - Визуализация: contribution graph (используй github-calendar)
   - Cache на 1 час (localStorage + timestamp)

2. NPM Widget:
   - Fetch из NPM API: /downloads/point/last-month/{package}
   - Показать: total downloads, monthly trend
   - Sparkline chart (используй recharts)

3. Dev.to Widget:
   - Fetch из Dev.to API: /articles?username={username}
   - Показать: последние 3 статьи с reading time
   - Lazy loading images

4. Architecture:
   - Создай React Context для кеширования
   - Используй SWR или TanStack Query
   - Error boundaries для каждого виджета
   - Skeleton loaders
```

**Критические детали:**
- GitHub API имеет rate limit (60 req/hour без токена) — добавь fallback на статические данные
- Для NPM API используй `https://api.npmjs.org/downloads/point/last-month/{package}`
- Dev.to API не требует авторизации для чтения

**Пример кода для GitHub Widget:**
```typescript
// src/lib/api.ts
export async function getGitHubStats(username: string) {
  const cacheKey = `github-${username}`;
  const cached = localStorage.getItem(cacheKey);
  
  if (cached) {
    const { data, timestamp } = JSON.parse(cached);
    if (Date.now() - timestamp < 3600000) return data;
  }

  const response = await fetch(`https://api.github.com/users/${username}`);
  const data = await response.json();
  
  localStorage.setItem(cacheKey, JSON.stringify({
    data,
    timestamp: Date.now()
  }));
  
  return data;
}
```

### Phase 3: MCP Server (60 минут) — **KILLER FEATURE**

**Задача:** Превратить портфолио в MCP-сервер.

**Требования:**
```markdown
1. Создать MCP-сервер на Fastify:
   - Endpoint: /mcp
   - Protocol: Streamable HTTP (не stdio)
   - Tools:
     * get_projects() → возвращает список проектов с метриками
     * get_engineering_principles() → возвращает твои принципы
     * analyze_stack(required_skills) → сравнивает твой стек с требованиями
     * simulate_architecture(project_id) → запускает симуляцию

2. Добавить MCP клиент в сайт:
   - На главной странице: "Ask AI about my experience"
   - Chat интерфейс (используй Vercel AI SDK)
   - Пользователь может спросить: "Какие проекты ты делал на React?"
   - AI вызывает get_projects() и отвечает

3. Документация:
   - README.md с инструкцией как подключить к Claude Code
   - Примеры запросов
   - JSON schema для каждого tool
```

**Критические детали:**
- Используй `@modelcontextprotocol/sdk` (официальный SDK)
- MCP-сервер должен быть в том же репозитории, но отдельным entry point
- Добавь CORS для localhost (для тестирования с Claude Desktop)

**Пример MCP Tool:**
```typescript
// src/mcp-server/tools.ts
import { z } from 'zod';

export const getProjectsTool = {
  name: 'get_projects',
  description: 'Get list of projects with live metrics',
  inputSchema: z.object({
    filter: z.enum(['all', 'react', 'typescript', 'aws']).optional()
  }),
  async execute({ filter }) {
    const projects = await fetchProjects();
    const filtered = filter 
      ? projects.filter(p => p.stack.includes(filter))
      : projects;
    
    return {
      projects: filtered.map(p => ({
        name: p.name,
        description: p.description,
        stars: p.github?.stars ?? 0,
        downloads: p.npm?.downloads ?? 0,
        stack: p.stack,
        liveUrl: p.url
      }))
    };
  }
};
```

## 🔥 Killer Features (чего еще никто не делал)

### 1. **"Reverse Interview" Mode**
- Посетитель (рекрутер) может запустить режим "Interview Me"
- AI (через MCP) задает вопросы на основе CV
- Показывает, как ты мыслишь в реальном времени
- В конце генерирует "compatibility score" с вакансией

### 2. **"Live System Design"**
- Для каждого проекта: интерактивная диаграмма
- Посетитель может "сломать" систему (добавить нагрузку, убрать компонент)
- Показывает, как твоя архитектура реагирует на изменения
- Доказывает, что ты понимаешь trade-offs

### 3. **"Engineering Principles Engine"**
- Не просто список принципов, а живые примеры
- Для каждого принципа (например, "Fail-closed by default"):
  * Реальный код из твоих проектов
  * Decision log: почему ты это выбрал
  * A/B тест: как было бы без этого принципа

### 4. **"Time Machine"**
- Git-like история твоего портфолио
- Посетитель может посмотреть, как выглядело портфолио год назад
- Показывает эволюцию твоего мышления
- Доказывает, что ты учишься и растешь

## 🐛 Gotchas (что может пойти не так)

1. **GitHub API Rate Limit**: Если ты часто перезагружаешь сайт, API заблокирует. Решение: кеш на 1 час.

2. **CORS для MCP**: Claude Desktop не может обращаться к localhost без CORS. Решение: добавь `Access-Control-Allow-Origin: *` в MCP-сервер.

3. **GitHub Pages Base Path**: Vite не знает, что сайт будет на `username.github.io/repo-name`. Решение: в `vite.config.ts` добавь `base: '/repo-name/'`.

4. **CodeSandbox Embed Limits**: Бесплатный план имеет лимиты. Решение: используй только для ключевых проектов.

5. **MCP SDK Version**: SDK быстро меняется. Решение: зафиксируй версию в `package.json`.
