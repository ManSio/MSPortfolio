### Nina Doinjashvili (Ninadnj/agent-memory-engine) — 1★, но идея — самая близкая нам

**Урок для нас:** философия «if it isn't measured, it isn't done» — **измеренное и опубликованное** впечатляет сильнее, чем 20 фич без чисел. Это ровно наша ось, и мы её не показываем.

## 2. Честный аудит MSPortfolio: «ерунда» vs реальное

### Что выглядит как «ерунда» (и почему разработчик это так прочитает)
| Элемент | Почему «ерунда» в глазах инженера |
|---|---|
| **ArchitectureSimulator** | Синтетические латентности из модели-игрушки, не замеры. Ярлык «simulation» есть, но инженер хочет «откуда эти числа?» |
| **Terminal на сайте** | Фейковый терминал — клише. |
| **Antipattern museum** | Милые истории, низкая техническая глубина. |
| **Load curves** | Те же синтетические данные, поданные как «лаборатория». |
| **verify_claim (главное!)** | **Циркулярность:** утверждения проверяются по данным, которые владелец сам написал. Острый инженер скажет: «вы проверяете себя по себе». Смягчено только verify_repo (живой GitHub). |
| **Много «стекла» и анимаций** | Презентация при пустом содержании = шум. |

### Что РЕАЛЬНО ценно (и скрыто в лаборатории)
| Актив | Почему впечатляет |
|---|---|
| **Эксперименты с командами и сырыми выводами** (mutmut 8%→100%, concurrency correctness, FTS5 vs pipeline) | Инженеры уважают измеренное и воспроизводимое. Ни у одного из 6 конкурентов такого нет. |
| **Отрицательные результаты** («не повторяй: ThreadPool для ONNX — RAM bottleneck») | Признак зрелости; НИКТО из списка так не делает. |
| **verify_claim с ОПУБЛИКОВАННЫМИ цифрами** (88% recall, 0 false-accept, p95 2.1s, команды в EXPERIMENTS_LOG) | Это published benchmark с контролями — ровно стиль Nina. Но спрятан в дневнике. |
| **14-туловый MCP-сервер, SSOT, dual-host, security-обвязка** | Реальная инженерная работа. |
| **Честный KI-борд** («by design» долги с температурой) | Редкая честность. |
| **Статьи на dev.to** | Работают на доверие. |

**Диагноз одной фразой:** реальная глубина (замеры, эвалы, честные провалы) спрятана в «лаборатории» на дне страницы, а первым делом посетитель видит симулятор-игрушку и фейковый терминал. Портфолио продаёт приколы вместо доказательств.

## 3. Что строить, чтобы реально удивить разработчиков (приоритет)

### Рекомендация 1 — «Опубликованный бенчмарк» (Nina-style; дёшево, максимально кредово)
Упаковать существующие замеры в **публичный воспроизводимый бенчмарк**:
- `pnpm bench` — прогон парафраз-набора + негативных контролей (v1 vs LLM arm) с выводом таблицы recall/precision/latency;
- закоммиченный файл результатов (как metrics.json) + **видимая секция «Benchmarks» на сайте**: claim verification 88% / 0 FA, mutation 8%→100%, concurrency 8/8.
- Усилие: ~0.5-1 день (в основном упаковка существующего). Эффект: «вот числа с командами» — язык, который разработчики понимают мгновенно.

### Рекомендация 2 — «Сломать циркулярность»: внешние arms проверки
verify_claim получает проверку по **внешним первоисточникам**, не только по самоописанным данным:
- GitHub (уже есть — verify_repo);
- dev.to (живые статьи, get_articles);
- npm/PyPI (существует ли пакет);
- README реальных репозиториев.
- Усилие: ~1-2 дня. Эффект: умирает главное возражение «проверяете себя по себе».

### Рекомендация 3 — «Проверь по коду» (долгосрочный wow, уникальный)
Связать портфолио-MCP с реальным кодом через mscodebase-intelligence (у владельца УЖЕ есть production MCP-сервер поиска по коду): демо «утверждение → проверка по фактическому коду репозитория». Ни у кого из 6 конкурентов нет проверки по коду. Усилие: значительное (публичный деплой кодового индекса). Эффект: потенциально уникальная позиция.

### Рекомендация 4 — «Убрать ерунду» (быстрый честный пас)
- Симулятор — подписать «интерактивная модель, не замеры» (или убрать);
- терминал/музей — демонтировать или резко ужать;
- лабораторию (эксперименты/эвалы/отрицательные результаты) — поднять вверх, сделать секцией №2.
- Усилие: полдня. Эффект: первое впечатление = глубина, а не приколы.

## 4. Вердикт

1. **У владельца есть редкий актив** — измеряемая эпистемическая дисциплина (evals, отрицательные результаты, честные долги), которой нет ни у одного конкурента из списка. Проблема — **презентация**: актив спрятан, «ерунда» впереди.
2. Самое дешёвое и кредовое — **Рекомендация 1** (публичный бенчмарк) + **4** (убрать ерунду): полтора дня, и портфолио начинает говорить языком инженеров.
3. **Рекомендация 2** закрывает единственное реальное архитектурное возражение (циркулярность).
4. **Рекомендация 3** — кандидат на «вау», но это отдельный проект.

*Ограничения: конкуренты прочитаны до уровня метаданных/README/структуры, не до каждой строки; цифры Nina (78%/93%) — с её сайта, не воспроизведены нами.*
